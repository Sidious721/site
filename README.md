# LogiQ RFQ backend

Маленький сервер на Node.js/Express, который принимает данные формы запроса ставки
с сайта (`#quote`) и отправляет их письмом на `a.egorov@logiq-freight.com`
(настраивается переменной `RFQ_TO_EMAIL` в `.env`).

Протестирован локально (валидация, honeypot, сборка запроса к почтовому API,
вложение, отклонение неподдерживаемых файлов, тайм-ауты) — подробности в конце
файла, раздел «Что реально проверено».

## Почему Resend, а не обычный SMTP

**Важно, если вы хостите backend на Render (или похожем бесплатном PaaS):**
с сентября 2025 года бесплатные тарифы Render блокируют весь исходящий SMTP-
трафик (порты 25, 465, 587) на уровне платформы — это защита от спама,
применяется у всех, независимо от того, насколько верно настроены пароли и
хост. Раньше этот backend использовал `nodemailer` с прямым SMTP-подключением
к Outlook, и на Render это приводило к бесконечному зависанию формы на сайте —
запрос уходил, но соединение молча "висело", пока браузер сам не сдавался по
тайм-ауту.

Сейчас backend отправляет письма через **HTTP API Resend** (`api.resend.com`) —
это обычный HTTPS-запрос на 443 порт, который никакой хостинг не блокирует.

## 1. Установка

```bash
cd backend
npm install
cp .env.example .env
```

Откройте `.env` и заполните реальными значениями (см. раздел 2 ниже).

## 2. Настройка Resend

1. Зайдите на **resend.com**, зарегистрируйтесь (бесплатно — 3000 писем в месяц,
   100 в день).
2. В панели → **API Keys** → **Create API Key** → скопируйте ключ (начинается
   с `re_`).
3. В `.env`:
   ```
   RESEND_API_KEY=re_ваш_скопированный_ключ
   ```

Готово — можно отправлять сразу же. По умолчанию письма уходят от адреса
`onboarding@resend.dev` — это тестовый адрес самого Resend, который работает
без дополнительной настройки. Ограничение касается только адреса
**отправителя** — присылать письма можно на любой настоящий адрес получателя
без ограничений (в т.ч. на `a.egorov@logiq-freight.com`).

### Когда подключите свой домен (необязательно, но лучше для доставляемости)

1. В панели Resend → **Domains** → **Add Domain** → впишите `logiq-freight.com`.
2. Resend покажет несколько DNS-записей (обычно TXT и MX) — добавьте их в
   панели DNS вашего домена (там же, где домен зарегистрирован/делегирован).
3. Подождите проверки (обычно до часа), в панели Resend появится галочка
   подтверждения.
4. В `.env` замените:
   ```
   FROM_EMAIL=LogiQ — заявки с сайта <noreply@logiq-freight.com>
   ```

Это не обязательно для того, чтобы форма заработала — но собственный домен
выглядит солиднее в письме и снижает шанс попадания в спам на длинной дистанции.

## 3. Запуск

```bash
npm start
```

Сервер поднимется на порту из `.env` (по умолчанию 3000) с двумя маршрутами:

- `GET /health` — проверка, что сервер жив
- `POST /api/rfq` — приём формы (multipart/form-data, те же поля, что в форме на сайте)

## 4. Деплой

Любой хостинг, который умеет запускать Node.js-процесс — теперь без оговорок
про SMTP-порты, так как исходящий трафик идёт только на 443:

- **Render.com** / **Railway.app** — подключаете репозиторий, задаёте
  переменные окружения из `.env` в панели, деплой в несколько кликов.
- **VPS** (свой сервер) — `npm install && npm start` за pm2/systemd, плюс nginx как reverse proxy.

После деплоя у вас будет публичный URL, например `https://logiq-rfq.onrender.com`.

## 5. Подключение к сайту

В `index.html` сайта найдите:

```js
var RFQ_ENDPOINT = ""; // TODO(владелец): вписать URL задеплоенного backend/api/rfq
```

Впишите туда адрес вашего backend + `/api/rfq`, например:

```js
var RFQ_ENDPOINT = "https://logiq-rfq.onrender.com/api/rfq";
```

И в `.env` backend'а укажите домен сайта в `ALLOWED_ORIGIN`, чтобы форма могла
слать запросы (иначе браузер заблокирует их по CORS):

```
ALLOWED_ORIGIN=https://ваш-домен.example
```

После этого форма на сайте начнёт реально отправлять заявки и показывать честный
success/error в зависимости от ответа сервера — код на фронтенде для этого уже готов,
менять его не нужно.

## Диагностика, если снова не работает

Backend теперь возвращает конкретные коды ошибок вместо зависания:

- `500 resend_not_configured` — забыли вписать `RESEND_API_KEY` в `.env` на хостинге.
- `500 server_error` (в логах — `API key is invalid` или похожее) — ключ
  скопирован неверно, лишний пробел, или ключ отозван в панели Resend.
- `504 resend_timeout` — сама Resend не ответила за 20 секунд (redko, обычно
  означает проблему на стороне Resend, а не у вас — попробуйте позже).
- Смотрите вкладку **Logs** в панели вашего хостинга (Render и т.п.) сразу
  после неудачной попытки отправки — там печатается точная причина.

## Что реально проверено

Не просто написан код — реально запущен (с временными заглушками вместо
express/multer и подменённым `fetch`, так как в среде разработки не было
доступа в интернет) и прогнан через настоящие HTTP-запросы:

- пустая форма → `400 missing_required_fields`;
- форма без галочки согласия на обработку данных → `400 consent_required`;
- заполненный honeypot (бот) → `200`, но запрос к Resend не формируется;
- полная валидная заявка с прикреплённым PDF → `200`, запрос к Resend собран
  верно: тема, `reply_to` на email клиента, все текстовые поля, чекбоксы
  корректно отражены как «да/нет», вложение в base64 с правильным именем файла;
- неверный/невалидный API-ключ Resend → `500`, ошибка залогирована с точной
  причиной от Resend;
- Resend не отвечает вовсе (эмулировано зависающим `fetch`) → `504
  resend_timeout` максимум через 20 секунд, а не бесконечное зависание;
- `RESEND_API_KEY` не задан вообще → `500 resend_not_configured`, понятная
  причина вместо непонятной ошибки;
- файл неподдерживаемого формата (`.exe`) → `400 unsupported_file_type`.

**Не проверено** (потому что физически невозможно в этой среде без интернета):
реальная отправка через настоящий Resend API и фактическая доставка письма
до почтового ящика. Сама логика запроса (что именно отправляется и куда)
проверена полностью — при реальном `RESEND_API_KEY` меняется только то, что
`fetch` идёт на настоящий сервер Resend вместо заглушки, код для этого не
переписывается.
