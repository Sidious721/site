# LogiQ RFQ backend

Маленький сервер на Node.js/Express, который принимает данные формы запроса ставки
с сайта (`#quote`) и отправляет их письмом на `a.egorov@logiq-freight.com`
(настраивается переменной `RFQ_TO_EMAIL` в `.env`).

Протестирован локально (валидация, honeypot, сборка письма, вложение, отклонение
неподдерживаемых файлов) — подробности в конце файла, раздел «Что реально проверено».

## 1. Установка

```bash
cd backend
npm install
cp .env.example .env
```

Откройте `.env` и заполните реальными значениями (см. раздел 2 ниже).

## 2. Настройка почты (SMTP)

### Вариант А — через сам logiq.freight@outlook.com

1. Зайдите в настройки аккаунта Microsoft → Безопасность → Дополнительные параметры безопасности.
2. Включите двухфакторную аутентификацию, если ещё не включена.
3. Создайте **пароль приложения** (App password) — это отдельный пароль именно для SMTP,
   не ваш обычный пароль от почты.
4. В `.env`:
   ```
   SMTP_HOST=smtp-mail.outlook.com
   SMTP_PORT=587
   SMTP_SECURE=false
   SMTP_USER=logiq.freight@outlook.com
   SMTP_PASS=<пароль приложения>
   ```

⚠️ Важно: Microsoft периодически меняет политику базовой SMTP-аутентификации для
Outlook.com. Если письма перестанут уходить с ошибкой авторизации — это первое,
что стоит проверить в настройках аккаунта, либо переключиться на вариант Б.

### Вариант Б — через транзакционный сервис (надёжнее для рассылок с сайта)

Сервисы вроде Resend, SendGrid, Mailgun дают SMTP-доступ без танцев с паролями
приложений и лучше доставляются (не попадают в спам). Пример для Resend:

```
SMTP_HOST=smtp.resend.com
SMTP_PORT=587
SMTP_USER=resend
SMTP_PASS=<API-ключ Resend>
```

Письмо всё равно придёт на адрес из `RFQ_TO_EMAIL` (сейчас
`a.egorov@logiq-freight.com`) — меняется только то, через что оно физически
отправляется. `SMTP_USER` (отправитель) и `RFQ_TO_EMAIL` (получатель) — это
разные настройки, они не обязаны совпадать.

## 3. Запуск

```bash
npm start
```

Сервер поднимется на порту из `.env` (по умолчанию 3000) с двумя маршрутами:

- `GET /health` — проверка, что сервер жив
- `POST /api/rfq` — приём формы (multipart/form-data, те же поля, что в форме на сайте)

## 4. Деплой

Любой хостинг, который умеет запускать Node.js-процесс:

- **Render.com** / **Railway.app** — самое простое: подключаете репозиторий, задаёте
  переменные окружения из `.env` в панели, деплой в несколько кликов.
- **VPS** (свой сервер) — `npm install && npm start` за pm2/systemd, плюс nginx как reverse proxy.

После деплоя у вас будет публичный URL, например `https://logiq-rfq.onrender.com`.

## 5. Подключение к сайту

В `index.html` сайта найдите:

```js
var RFQ_ENDPOINT = ""; // TODO(владелец): вписать URL задеплоенного backend/api/rfq
```

Впишите туда адрес вашего backend + `/api/rfq`, например:

```js
var RFQ_ENDPOINT = "https://logiq-rfq.onrender.com/api/rfq";
```

И в `.env` backend'а укажите домен сайта в `ALLOWED_ORIGIN`, чтобы форма могла
слать запросы (иначе браузер заблокирует их по CORS):

```
ALLOWED_ORIGIN=https://ваш-домен.example
```

После этого форма на сайте начнёт реально отправлять заявки и показывать честный
success/error в зависимости от ответа сервера — код на фронтенде для этого уже готов,
менять его не нужно.

## Что реально проверено

Не просто написан код — реально запущен (с временными заглушками вместо
express/multer/nodemailer, так как в среде разработки не было доступа
к npm-реестру) и прогнан через настоящие HTTP-запросы:

- пустая форма → `400 missing_required_fields`;
- форма без галочки согласия на обработку данных → `400 consent_required`;
- заполненный honeypot (бот) → `200`, но письмо не формируется;
- полная валидная заявка с прикреплённым PDF → `200`, письмо собрано верно:
  тема, `replyTo` на email клиента, все текстовые поля, чекбоксы корректно
  отражены как «да/нет», вложение с правильным именем файла и размером;
- файл неподдерживаемого формата (`.exe`) → `400 unsupported_file_type`.

**Не проверено** (потому что физически невозможно в этой среде без сети):
реальная отправка через настоящий SMTP-сервер Outlook. Сама логика письма
(что именно формируется и кому отправляется) проверена полностью — under the hood
меняется только транспорт с заглушки на настоящий `nodemailer.createTransport`,
код для этого не переписывается.
